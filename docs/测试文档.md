## 2. 测试计划

### 2.1 测试范围

| 测试类型 | 覆盖范围 | 优先级 |
|---------|---------|--------|
| **功能测试** | 文档管理、智能问答、MCP 搜索、三记忆、监控看板 5 大模块 | P0 |
| **集成测试** | 文档→检索→生成→引川→反馈全链路数据流 | P0 |
| **用户验收测试** | PRD 中 5 条用户故事逐条验证 | P0 |
| **安全测试** | 多用户数据隔离、API Key 保护 | P0 |
| **性能测试** | 检索延迟、文档导入耗时、重排序体感 | P1 |
| **兼容性测试** | 浏览器、LLM 后端切换 | P1 |
| **算法评测** | 检索精度 + 生成质量（详见 `eval_data.md`，本档不重复） | P1 |

### 2.2 测试环境

| 项目 | 说明 |
|------|------|
| 服务器 | Railway 云平台 + 本机 Docker Compose |
| 数据库 | ChromaDB（嵌入式）、SQLite（`data/metadata.db`）、Neo4j（Docker 容器） |
| LLM | 默认 qwen-turbo（DashScope），备用 DeepSeek/Ollama 本地 |
| 嵌入模型 | text-embedding-v4（API），备用 BAAI/bge-small-zh-v1.5（本地） |
| 浏览器 | Chrome 120+ / Firefox 120+ / Edge 120+ |
| 测试用户 | 至少 2 个独立用户名，用于验证数据隔离 |

### 2.3 缺陷严重等级

| 等级 | 定义 | 示例 |
|------|------|------|
| **P0-阻塞** | 核心链路中断，用户无法完成主要任务 | 提问后页面白屏、上传文档后检索不到 |
| **P1-严重** | 功能可用但有明显错误 | 引川指向错误文档、反馈数据未入库 |
| **P2-一般** | 不影响使用但体验差 | 加载耗时未显示、错误提示不友好 |
| **P3-建议** | 优化建议 | 文案可以更清晰、按钮位置调整 |

## 9. 已知缺陷与待优化项

| ID | 缺陷描述 | 严重等级 | 影响范围 | 计划 |
|----|---------|---------|---------|------|
| BUG-01 | BGE Reranker CPU 推理延迟 ~25s，用户体验差 | P2 | 启用重排序功能的用户 | 待 GPU 推理或换轻量模型（bge-reranker-base ~300MB） |
| BUG-02 | Streamlit 单进程架构不支持真实并发 | P2 | 多用户场景 | 生产环境需 Gunicorn 多 worker 或换 FastAPI |
| BUG-03 | 纯图片 PDF 解析为空文本 | P2 | 上传扫描件 PDF 的用户 | 待集成 OCR（规划中） |
| BUG-04 | RAGAS Faithfulness 聚合因 NaN 传播导致静默失败 | P3 | 评测脚本 | 已修复：`_nanmean()` 过滤 NaN 后求均值 |
| BUG-05 | 本地嵌入模型在技术文档上 R@10 降低 ~15pp（vs API 嵌入） | P3 | 使用本地嵌入的用户 | 可切换更高维本地模型或优化分块策略 |
