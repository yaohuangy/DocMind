## 2. 产品概述

### 2.1 项目背景与目标

**三大痛点：**

1. **文档越积越多，找不到**：个人和团队在日常工作中积累大量文档（技术方案、学习笔记、项目报告），传统关键词搜索只能做浅层字符匹配，无法理解语义——用户换一种问法就找不到答案。
2. **大模型无法对接私有文档**：GPT、Claude 等通用大模型虽能理解自然语言，但训练数据不包含用户的私有文档，且存在幻觉问题——编造不存在的事实。
3. **碎片化 Q&A 无法沉淀**：每次问答独立进行，历史提问和回答没有被关联利用，用户无法从过往的碎片化交互中提炼知识结构。

**产品目标**：打造一个面向个人知识管理的智能文档问答助手，让用户用自然语言对私有文档提问，获得准确、可溯源的答案，并通过记忆系统将碎片 Q&A 逐步沉淀为个人知识图谱。

### 2.2 产品定位与价值

> **一句话定位**：一个面向个人用户的、基于私有文档的智能问答助手，提供即时准确的答案引用与长期知识积累。

核心价值：

- **准确**：答案强制引用原文来源，用户可追溯验证
- **智能**：理解口语化提问，自动选择最优检索策略
- **积累**：三记忆模型将每次问答转化为长期知识沉淀
- **可控**：数据本地存储，Token 成本实时可见

### 2.3 成功指标

| 类别 | 指标 | 目标值 | 当前值 |
|------|------|--------|--------|
| 检索质量 | MRR（平均倒数排名） | ≥ 0.70 | 0.75 |
| 检索质量 | Recall@10 | ≥ 55% | 57.8% |
| 生成质量 | Faithfulness（忠实度） | ≥ 0.85 | 0.87 |
| 响应速度 | 简单查询 P95 延迟 | ≤ 0.5s | 0.37s |
| 响应速度 | 复杂查询 P95 延迟 | ≤ 3s | 2.3s |
| 成本控制 | 简单查询 Token 消耗 | 0 | 0 |
| 用户满意度 | 👍 占比 | ≥ 80% | 线上运行追踪中 |

## 6. 功能详述

### 6.1 文档管理

**前置条件**：用户已登录（输入用户名）

**功能描述**：
- 支持 8 种格式文档上传：PDF、Word(.docx)、Markdown(.md)、TXT、PPT(.pptx)、CSV、Excel(.xlsx)、网页 URL
- 上传后自动触发 5 步处理管线：格式识别 → 分块（语义分块，512 token / 128 overlap） → 向量化嵌入 → ChromaDB 入库 → SQLite 元数据记录
- 支持按格式筛选、查看文档详情、单条删除
- 文档页面显示上次加载耗时 + 每步耗时分解

**正常流程**：
1. 用户上传文件/粘贴 URL
2. 系统识别格式 → 分发到对应解析器
3. 解析为纯文本 → 语义分块 → 嵌入向量 → 存入 ChromaDB
4. SQLite 记录 doc_id、文件名、格式、分块数、总耗时
5. 页面展示加载完成，显示各步骤耗时

**异常流程**：
- 上传不支持的文件格式 → 提示"当前支持 PDF/Word/Markdown/TXT/PPT/CSV/Excel/网页 URL"
- 文件损坏/无法解析 → 记录错误，跳过该文件，不影响其他文件
- URL 无法访问 → Trafilatura 解析失败时自动切换 BeautifulSoup 兜底
- 同一文件重复上传 → 以 doc_id 去重，旧分块先清空再重建

**边界条件**：
- 空文件（0 字节） → 拒绝，提示"文件无内容"
- 超大文件（>50MB） → 提示"建议拆分为多个文件"
- 纯图片 PDF → 解析为空文本，记录在元数据中

### 6.2 智能问答

**前置条件**：用户已登录，知识库至少有一篇文档

**功能描述**：
- 用户输入自然语言问题，选择检索策略（Direct/MQE/HyDE/MQE+HyDE），系统返回流式答案
- 答案中标注引用标记 `[1][2]`，点击可展开对应原文片段
- 每条回答下方提供 👍👎 反馈按钮

**正常流程**：
1. 用户输入问题，选择检索方法（或使用动态路由自动选择）
2. 系统根据选择执行检索：Direct 直接向量搜索（~0.25s） / HyDE 先生成假设答案再搜索（~1.9s） / MQE 多角度改写后并行搜索（~1.3s）
3. 检索结果经过去重（bigram Jaccard，阈值 0.65）+ 可选重排序（BGE Reranker）
4. 拼接上下文 → 送入 LLM 生成答案 → 流式输出到界面
5. 答案末尾渲染引用标记，可点击展开

**异常流程**：
- 检索结果为空（所有分块相似度 <0.2） → 提示"未找到相关内容，建议换种问法或上传相关文档"
- LLM 生成超时 → 提示"回答生成超时，请稍后重试"
- HyDE 假设生成幻觉 → 相似度 <0.3 时丢弃，回退 Direct
- 用户连续快速提问 → 不阻塞，各自独立处理

**边界条件**：
- 用户输入为空 → 禁用发送按钮
- 输入超长（>2000 字） → 截断前 2000 字并提示
- 知识库为空 → 提示"请先上传文档"
- 选择 MQE+HyDE ——两个 LLM 调用 asyncio.gather 并行，延迟 ≈ max(分支)

### 6.3 MCP 外部搜索

**前置条件**：已配置 Tavily API Key，本地检索结果不理想时触发

**功能描述**：
- 当系统判断问题需要外部信息（时效性/新闻/趋势类）或本地检索结果低于阈值时，自动调用 Tavily 联网搜索
- 本地结果 `[N]` 和外部结果 `[E]` 区别标注
- 规则引擎（正则匹配零 Token）+ LLM 分类兜底双模路由，准确率 93%

**正常流程**：
1. 问题进入路由判断 → 规则引擎匹配（如"今天""最新""2026"触发联网）
2. 规则无法判断时由 LLM 分类
3. 外部搜索结果去重（与本地重复的剔除）
4. 本地 + 外部结果交错排列（L1→E1→L2→E2）
5. LLM 融合生成，`[N]` 和 `[E]` 区分引用

**异常流程**：
- Tavily API 不可用 → 降级为纯本地检索
- 外部搜索结果为空 → 仅返回本地结果
- API 配额耗尽 → 提示"联网搜索暂不可用，使用本地结果"

### 6.4 三记忆系统

**前置条件**：至少进行一次问答

**功能描述**：

| 记忆层 | 存储 | 机制 | 用户价值 |
|--------|------|------|---------|
| 工作记忆 | st.session_state | 最近 10 轮 Q&A，超 10 轮触发 LLM 压缩 | 多轮对话不遗忘上下文 |
| 情景记忆 | ChromaDB | Q&A 持久化 + 语义搜索 + 时间过滤 | 可搜历史问题和回答 |
| 语义记忆 | Neo4j | LLM 自动抽取 3-8 个概念 → MERGE 节点 → 建立弱关系 | 知识图谱自构建 |

**正常流程**：
1. 每次问答结束后触发 MemoryManager
2. 工作记忆：添加 Q&A 摘要 → 超阈值时 LLM 压缩（保最近 3 轮原文 + 历史摘要）
3. 情景记忆：存入 ChromaDB episodic_memory collection
4. 语义记忆：LLM 抽取概念（逗号分隔） → Neo4j MERGE 节点 → pairwise RELATES_TO 弱关系

**异常流程**：
- Neo4j 不可用 → 语义记忆自动禁用，工作记忆 + 情景记忆正常运行，前端不报错
- LLM 概念抽取失败 → 三级回退解析（逗号分隔 → 换行分割 → 单条记录）

### 6.5 监控看板

**功能描述**：
- 实时展示：总反馈数、满意度（👍 占比）、P50/P95 检索延迟
- 各方法对比：按 Direct/MQE/HyDE/MQE+HyDE 分组展示满意率柱状图 + 平均延迟
- Token 成本：总 Token、输入/输出比、各方法 Token 消耗、预估费用（¥）
- 最近反馈列表：最近 10 条 👍👎 记录，支持单条删除

## 7. Prompt 策略与质量评估

### 7.1 Prompt 体系

| Prompt | 用途 | 说明 |
|--------|------|------|
| RAG_QA_SYSTEM | 标准问答 | 带上下文 + 引用要求 |
| RAG_QA_NO_CONTEXT | 知识库无结果 | 自然拒绝 + 建议 |
| RAG_QA_WITH_EXTERNAL | MCP 融合搜索 | 区分 `[N]`/`[E]` 引用 |
| QUERY_VARIANTS | MQE 查询变体 | 4 角度（定义/机制/对比/应用） |
| HYPOTHETICAL_ANSWER | HyDE 假设文档 | 200-400 字假想答案 |
| CONCEPT_EXTRACTION | 概念提取 | 逗号分隔，三级回退解析 |
| QUERY_CLASSIFY | 复杂度分类 | simple/complex，93% 准确率 |
| LEARNING_REPORT | 学习报告 | 知识图谱摘要 + 建议 |

### 7.2 Prompt 质量评估标准

| 维度 | 定义 | 评估方式 |
|------|------|---------|
| 忠实度 | 答案是否严格基于提供的文档片段 | RAGAS Faithfulness（≥ 0.85） |
| 相关性 | 答案是否直接回应问题 | RAGAS Answer Relevancy（≥ 0.75） |
| 引用准确性 | 引用标记是否对应真实文档片段 | 人工抽检 + 自动化正则校验 |
| 拒答合理性 | 知识库无内容时应拒绝而非瞎编 | 评测集覆盖无答案场景 |

### 7.3 Prompt 变更流程

1. 修改 Prompt 模板文件
2. 跑离线评测 → 对比改动前后的指标变化
3. 若指标下降 → 回滚；若持平或提升 → 合并
4. 重大 Prompt 变更后手动验证 5-10 条代表性问答

- 浏览器：Chrome/Firefox/Edge 最新两个大版本
- 部署环境：Docker（推荐）、本机 Python 3.10+、Railway 云平台
- 多平台 LLM 后端兼容：DashScope / DeepSeek / OpenAI / Ollama 本地

### 8.4 可维护性

- 代码规范：Ruff lint + mypy 严格类型检查（零错误）
- 自动化测试：GitHub Actions CI，173 个测试用例
- 配置管理：`.env` 单文件管理全部环境变量，`.env.example` 模板

## 9. AI 专项风险与降级策略

### 9.1 风险矩阵

| 风险 | 影响 | 概率 | 缓解措施 | 状态 |
|------|------|------|---------|------|
| LLM 幻觉（HyDE 假设生成编造概念） | 检索偏离，答案不准确 | 中 | 语义相似度 <0.3 丢弃 HyDE，回退 Direct | ✅ |
| LLM 幻觉（生成答案编造引用） | 用户信任崩塌 | 低 | 强制引用源码片段，无引用标记的回答标记为"低置信度" | ✅ |
| Token 成本失控 | 透支 API 配额 | 中 | 动态路由（简单走 Direct 零 Token）、对话压缩 -75%、监控页成本追踪 | ✅ |
| Neo4j 不可用 | 语义记忆失效 | 低 | 自动降级禁用，工作/情景记忆正常运行 | ✅ |
| 嵌入 API 限流 | 文档导入中断 | 低 | 批量嵌入（10 条/批），失败重新排队 | ✅ |
| Reranker 延迟过高 | 用户等待感明显 | 高 | CPU 推理 ~24s，已识别为瓶颈 → 待 GPU 或轻量模型优化 | ⚠️ |
| 评测指标与用户体验脱节 | 指标好但用户不满意 | 中 | 监控页持续追踪 👍👎 满意率，不只看离线指标 | ✅ |
| LLM API 不可用 | 系统完全瘫痪 | 低 | 提示用户当前不可用 + 仅展示检索片段（不生成答案） | 🚧 |

### 9.2 降级策略总览

```
LLM API 挂了 → 仅返回检索片段 + 提示稍后重试
Embedding API 挂了 → 文档导入阻塞，已有文档问答正常
Neo4j 挂了 → 语义记忆禁用，问答/笔记/情景记忆正常
大模型换了 → 离线评测跑回归测试，指标不降级再上线
Token 快耗尽 → 强制 Direct 模式（零 Token）
Tavily 挂了 → 纯本地检索
```

## 11. 上线与回滚计划

### 11.1 部署方案

| 环境 | 说明 |
|------|------|
| 本地开发 | `python run.py`，默认 `localhost:7860` |
| Docker | `docker-compose up -d`，一键启动 Streamlit + Neo4j |
| 生产环境 | Railway 云平台，自动 HTTPS，持久化 Volume，公网域名 |

### 11.2 上线流程

1. 代码合入 main 分支 → GitHub Actions 自动执行 ruff + mypy + pytest
2. CI 全绿后 → 构建 Docker 镜像
3. 推送镜像 → Railway 自动部署（或手动 `docker-compose up -d`）
4. 部署后冒烟测试：上传测试文档 → 提问 5 条 → 检查引川和延迟 → 确认 👎 反馈能写入
5. 观察监控看板 30 分钟确认无异常

### 11.3 回滚方案

| 场景 | 回滚方式 |
|------|---------|
| 新版本答案质量显著下降 | `git revert` → 重新部署上一版本镜像 |
| Neo4j 故障 | 自动降级，无需回滚；修复后重启 Neo4j 即恢复 |
| LLM API 故障 | 切换 `.env` 中的 `LLM_BASE_URL` 到备用后端 |
| Docker 镜像问题 | `docker-compose down` → 切换旧 tag → `docker-compose up -d` |
| 数据损坏 | ChromaDB/SQLite 数据目录通过 Volume 持久化，恢复 `data/` 备份 |

### 11.4 数据监控

上线后重点观察：

- 首 1 小时内：P95 延迟是否异常飙升、错误日志数量
- 首 24 小时内：👍 占比是否低于基准线、Token 消耗是否异常
- 首 1 周内：MRR 离线评测结果是否与线上满意度一致
